Large surveys (out-of-core)

build_octree("county.las", "county_octree")    # once; streams the file, bounded RAM
scene = Scene()
load!(scene, "county_octree"; point_budget = 4_000_000)
open_viewer(scene)

A 3M-point file converts in about 5 s. Coarse octree levels add about 10% storage over the raw points.

SpatialRender.build_octree — Function
build_octree(source, out_dir; node_capacity=50_000, bucket_points=4_000_000,
             spacing_div=128, chunk=1_000_000, seed=1) -> out_dir

Convert a point cloud for out-of-core rendering with OctreeCloud. source is a LAS file path or a PointCloud (whose coordinates are taken as already local).

  • node_capacity: maximum points stored in one node.
  • bucket_points: target points per on-disk bucket. Peak memory is about bucket_points × 24 bytes plus write buffers.
  • spacing_div: subsampling grid per node edge; larger keeps more points in coarse nodes.

The LAS path is read in chunk-point slices through a memory map, so files larger than RAM convert. Coordinates are stored relative to the cloud's centre (an OffsetFrame recorded in octree.json).

SpatialRender.OctreeCloud — Type
OctreeCloud(dir; point_budget=3_000_000, min_node_pixels=80, point_size=2, color_mode)

A point cloud converted with build_octree and streamed from disk. With adaptive_size (default) each node's points are drawn at a world size matching that node's point spacing (never below point_size pixels), so coarse regions read as continuous surfaces rather than sparse dots.

Streaming details: only the nodes that matter for the current view are loaded (on a background thread) and kept on the GPU, within point_budget points. Nodes are refined while their projected size exceeds min_node_pixels.

The layer's coordinates are relative to frame(cloud) (an OffsetFrame at the data centre); load other data with that frame to overlay it.
