SpatialRender.SpatialRender — Module
SpatialRender

A native OpenGL renderer for meshes, LiDAR point clouds, GIS vector layers and trajectories in one scene, built for diagnostic views in robotics and aerial systems.

The package has two halves:

  • a GPU-free core (ingestion, local frames, filters, BVH / k-d tree indexing, frustum culling, ray picking, camera) that can be used and tested headless;
  • an OpenGL 4.1 core-profile backend (GLFW window, interleaved vertex buffers, point / mesh / line shader pipelines, render loop).

Quick start:

using SpatialRender
scene = Scene()
add!(scene, load_mesh("part.stl"))
load!(scene, "scan.las")   # sets the scene frame from the file
open_viewer(scene)

SpatialRender.AttributeOutlierFilter — Type
AttributeOutlierFilter(; attributes=(:z, :intensity), method="mad", threshold=nothing, window=7)

One-dimensional outlier rejection on per-point attributes (:x, :y, :z, :intensity); a point is dropped when any listed attribute is an outlier. Methods: "zscore", "iqr", "mad" (default, robust) and "hampel" (a moving-window MAD along acquisition order, GPS time when present, which follows a drifting signal: intensity spikes along a scan line).

The statistics are computed by the KaosCleaner engine: using KaosCleaner enables this filter (package extension).

SpatialRender.GroundPlaneFilter — Type
GroundPlaneFilter(; threshold=0.15, iterations=200, max_tilt=15, mode=:remove, seed=1)

Fit the dominant near-horizontal plane with RANSAC (normal within max_tilt degrees of +Z) and treat points within threshold metres of it as ground.

  • mode=:remove drops ground points (obstacle / structure views);
  • mode=:keep keeps only ground points;
  • mode=:classify keeps everything and sets ASPRS class 2 (ground) on the inliers, so the classification color mode shows them.

SpatialRender.OctreeCloud — Type
OctreeCloud(dir; point_budget=3_000_000, min_node_pixels=80, point_size=2, color_mode)

A point cloud converted with build_octree and streamed from disk. With adaptive_size (default) each node's points are drawn at a world size matching that node's point spacing (never below point_size pixels), so coarse regions read as continuous surfaces rather than sparse dots.

Streaming details: only the nodes that matter for the current view are loaded (on a background thread) and kept on the GPU, within point_budget points. Nodes are refined while their projected size exceeds min_node_pixels.

The layer's coordinates are relative to frame(cloud) (an OffsetFrame at the data centre); load other data with that frame to overlay it.

RenderSettings(; kwargs...)
  • background: clear color.

SpatialRender.build_octree — Method
build_octree(source, out_dir; node_capacity=50_000, bucket_points=4_000_000,
             spacing_div=128, chunk=1_000_000, seed=1) -> out_dir

Convert a point cloud for out-of-core rendering with OctreeCloud. source is a LAS file path or a PointCloud (whose coordinates are taken as already local).

  • node_capacity: maximum points stored in one node.
  • bucket_points: target points per on-disk bucket. Peak memory is about bucket_points × 24 bytes plus write buffers.
  • spacing_div: subsampling grid per node edge; larger keeps more points in coarse nodes.

The LAS path is read in chunk-point slices through a memory map, so files larger than RAM convert. Coordinates are stored relative to the cloud's centre (an OffsetFrame recorded in octree.json).

SpatialRender.build_point_index — Method
build_point_index(pc; chunk_size=8192, seed=1) -> PointIndex

Reorders pc.vertices (and pc.gps_time) in place into spatially coherent chunks of at most chunk_size points (median splits on the longest axis) and shuffles points within each chunk. Extra memory while building is one Int32 permutation (4 bytes per point); what stays is one entry per chunk.

SpatialRender.configure_gpu! — Method
configure_gpu!(; candidates=nothing, force=false) -> String

Make OpenGL use a hardware GPU on WSL2 (see the comment at the top of src/render/gpu_select.jl). Called automatically before the first window; returns a description of what was selected.

Does nothing when not on WSL, when GALLIUM_DRIVER is already set (your choice wins), or when SPATIALRENDER_GPU_AUTOCONFIG=0. candidates are adapter-name substrings to try in order (default: an explicitly set MESA_D3D12_DEFAULT_ADAPTER_NAME, else NVIDIA, AMD, Intel, then Mesa's default adapter).

probe (returns the renderer string of a fresh context, or nothing), reinit and wsl exist so tests can simulate drivers; leave them alone.

SpatialRender.cull! — Method
cull!(index, frustum; eye, pixels_per_radian=Inf, density=1.0, min_points=256) -> VisibleRanges

Fill index.visible with the draw ranges of chunks inside frustum.

Level of detail: a chunk whose bounding sphere covers A pixels on screen (computed from the distance to eye and pixels_per_radian) draws at most density × A of its points, never fewer than min_points. Because chunks are shuffled, the drawn prefix is a uniform subsample. Pass pixels_per_radian=Inf to always draw every point.

Adjacent full chunks are merged into one range. Allocation-free.

SpatialRender.gis_layer — Function
gis_layer(geometries; frame=nothing, color, width=2, height=0, name="gis") -> (LineLayer, PointCloud, frame)

Convert GeoInterface-compatible geometries (a GeoDataFrames geometry column, Shapefile.jl / GeoJSON.jl / LibGEOS objects, …) into a line layer and a point-marker layer, like load_geojson.

Coordinates go through frame: with an ENUFrame (or frame=nothing, which builds one at the data centre) they must be longitude/latitude, so reproject projected layers to EPSG:4326 first; with an OffsetFrame they are used as projected metres directly.

Needs using GeoInterface (or any package that loads it, such as GeoDataFrames).

SpatialRender.load! — Method
load!(scene, path; kwargs...) -> scene

Load any supported file into scene in the scene's frame.

When the scene is still empty and uses an IdentityFrame, georeferenced data sets the frame: a LAS file sets an OffsetFrame at its centre, a GeoJSON file an ENUFrame at its centre. Later files reuse that frame. A directory written by build_octree loads as an OctreeCloud.

source
SpatialRender.load_geojson — Method
load_geojson(path; frame=nothing, color, width=2, height=0, name) -> (LineLayer, PointCloud, frame)

Read a GeoJSON file. Lines and polygon rings become a LineLayer; Point/MultiPoint features become a PointCloud of markers.

Coordinates are taken as WGS84 longitude/latitude and reprojected into frame. With frame=nothing an ENUFrame at the centre of the data's lon/lat bounds is used. height is added to 2-D coordinates (drape boundaries slightly above terrain). A feature property "stroke" holding a #rrggbb color overrides color.

For shapefiles, GeoPackage and other OGR formats load GeoDataFrames and use gis_layer (a package extension).

source
SpatialRender.load_las — Method
load_las(path; frame=nothing, name=basename(path), gps_time=false, stride=1,
         classes=nothing) -> (PointCloud, frame)

Read a LAS file through a memory map.

  • frame: local frame for the points. When nothing, an OffsetFrame at the centre of the file's bounding box is used. The frame is returned too, so other layers can be loaded into the same coordinates.
  • stride: keep every stride-th point (quick previews of huge files).
  • classes: keep only these ASPRS classes, e.g. classes=[2, 6].
  • gps_time: also read per-point GPS time (formats 1, 3–10).

Intensity is normalised to 0–1 by the largest value in the file; 16-bit RGB is reduced to 8 bits.

SpatialRender.load_obj — Method
load_obj(path; frame=IdentityFrame(), scale=1, name=basename(path)) -> TriMesh

Read a Wavefront OBJ. Polygons are fan-triangulated; each distinct v/vt/vn combination becomes one GPU vertex. Missing normals are computed. OBJ files from modelling tools are usually Y-up: pass up=:y to convert them to the scene's Z-up convention.

source
SpatialRender.load_stl — Method
load_stl(path; smooth=false, frame=IdentityFrame(), name=basename(path), scale=1) -> TriMesh

Read a binary or ASCII STL file.

With smooth=false (the default, right for CAD parts) every facet keeps its own three vertices and the facet normal, so hard edges stay hard. With smooth=true coincident vertices are welded and normals averaged. scale converts units (e.g. scale=1e-3 for millimetre CAD into metres). up=:y converts a Y-up model (common from 3D modelling tools) to the scene's Z-up convention.

SpatialRender.open_bag — Method
open_bag(path; scene=Scene(), fixed_frame=nothing, topics=nothing, cloud_capacity=2_000_000,
         history=3.0, intensity_range=nothing, marker_size=nothing) -> BagPlayer

Open a ROS 2 bag (an .mcap file or a rosbag2 directory) for replay into scene and add a layer per supported topic:

message typeshown as
sensor_msgs/PointCloud2streaming cloud, each scan placed via TF at its stamp
nav_msgs/Odometry, PoseStampedfull trajectory + an axes marker at the current pose
nav_msgs/Paththe latest path at the current time
sensor_msgs/NavSatFixENU track, first fix anchored at the robot's pose

/tf and /tf_static build the frame tree. Everything is drawn in fixed_frame (default: map, world, odom, else the tree's root). history seconds of scans stay visible (:auto: enough for the sparsest point cloud topic, 3–30 s). Sensor frames missing from TF (typically when /tf_static was not recorded) are drawn at the robot frame with missing_frames = :robot (or untransformed with :origin, or not at all with :skip); give the real mountings with static_transforms = [StampedTransform(...)]. TF is interpolated only across gaps up to max_tf_gap seconds. With skip_gaps, playback jumps over stretches with no messages. topics restricts which topics are shown.

SpatialRender.trajectory — Method
trajectory(positions; frame=IdentityFrame(), times=nothing, colormap=:time,
           color=Vec4f(0.2, 0.8, 1, 1), width=3, name="trajectory") -> LineLayer

Turn a sequence of positions (a vector of 3-vectors, or a 3×N / N×3 matrix) into a line layer. With colormap=:time (default) the path is shaded from blue (start) to red (end) along times (or the sample index), which makes loops and revisits easy to read. Use colormap=:solid for one color. max_gap (in the units of times) breaks the line wherever consecutive samples are further apart, so recording gaps don't show as straight jumps.

Positions go through frame, so GNSS fixes can be given as (lon, lat, h) with an ENUFrame.
